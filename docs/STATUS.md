An Apple chain imported under a guessed original id (no In-App Purchase key, or Apple did not answer) is re-keyed when store traffic proves the real one or a later import run confirms it; without the In-App Purchase key, a store notification for a renewal the export never saw cannot be matched until the device posts a receipt.

- The SDK compatibility panel says whether contract tests cover an SDK's major version; it does not score per-feature coverage like RevenueCat's panel.

AppsFlyer web APIs, Meta's App Events API, paywall events, export column selection, Azure and email destinations and IAM-role credentials are not built.
- OpenAPI schema checks skip when RevenueCat's spec is not on disk (public CI), so they run only on machines with the research copy.
- Refund Control sends Send Consumption Information V1; Apple's newer V2 (consumption percentage, prorated refunds) is not used yet. `playTime` is undeclared unless the app sets `rd_play_time_minutes`. Win-back email on Cloud comes from `no-reply@mail.revenuedot.app` (Reply-To the project's support email); no custom sending domains, and the Cloudflare binding sends no `List-Unsubscribe` header. Lifecycle lists, previews and policy counts scan at most 10,000 customers.
- Charts: segmenting a money chart by a purchase dimension (product, store, offering) puts ad revenue, which has no product, in every segment; no tax data (revenue net of taxes equals revenue), paid intro offers count as direct purchases, no renewal-cycle, offer-type or custom-attribute dimensions (attribution dimensions are built on `tier3-insights`), platform and app version are the customer's latest, App Store Save Outcomes is always zero, and charts are computed per request (large projects will need daily rollups). See `prd/charts/PRD.md`.
