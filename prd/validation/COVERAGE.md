## How it is tested
- **Journeys** (`pnpm tsx scripts/e2e/journeys/run.ts [name]`) use RevenueDot the way a developer and their end users do: the real Node server (`apps/server/src/entry.node.ts`) with the built dashboard, on a fresh database on the Railway development Postgres (dropped after the run), accounts made through the real `/auth/signup`, the real SDKs or their exact wire calls, Chromium through Playwright, email over SMTP to a local sink. Each journey checks the result through the v2 API, direct SQL, delivered webhooks, emails and the dashboard.
- **Outbound calls** go through a fetch preload (`scripts/e2e/journeys/lib/outbound-preload.mjs`) that acts as DNS: partners, Stripe, Amazon and Google APIs are answered by fakes on a local capture server, Apple's and Google Play's hosts are blocked, and Google Analytics Measurement Protocol hits go to Google's real validation server. The server's own code (store adapters, delivery code, the outbound guard) runs unchanged.
- **The test suites** (`pnpm vitest run`, including `ee/test`: 116 files, 1,316 tests pass and 1 file is skipped unless `PAYWALL_DECODE=1`; 2026-10-02 on the final code, locally and in CI's `test` and `test-postgres` jobs) run on in-memory PGlite, and on real Postgres with `REVENUEDOT_TEST_PG_URL` (one database per test file, dropped at the end). CI runs both (`test` and `test-postgres` jobs).
- **The dashboard's e2e suite** (`pnpm --filter @revenuedot/dashboard e2e`, 27 spec files) clicks through the dashboard in Chromium against the real API on the in-memory server: 60 tests pass and 4 screenshot-only tests skip (2026-10-02, on the final code, after fixing `assistant.spec.ts`, whose last check expected the Overview's ask bar on a first-run project). CI does not run it yet.
- **The enterprise browser suite** (`bash ee/e2e/run.sh`) runs the organization, SSO (SAML and OpenID Connect against a local test identity provider) and SCIM pages in Chromium on a database of its own on the Railway development Postgres: 35 tests pass (2026-10-02).
- **Fakes** are named as fakes below. No real App Store, Google Play, Amazon, Stripe or partner account is used. `~/.config/revenuedot/prod.env` (names checked, values never read) has no Stripe test-mode key, no model key and no partner key. It does hold an App Store In-App Purchase key (`APPLE_IAP_*`) and a Play service account (`GOOGLE_PLAY_SERVICE_ACCOUNT_FILE`), but this suite never calls Apple or Google: the stores are checked against generated certificates and fakes, and real sandbox purchases need a device signed in to a sandbox account.
